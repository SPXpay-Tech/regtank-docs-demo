Exchange API

Submit individuals, businesses, and crypto transactions for compliance screening — and receive results through polling or webhooks.

Get an access token → Download OpenAPI spec
curl · 30-second smoke test 
## 1. Get an access token (valid 1 hour)
TOKEN=$(curl -sX POST https://crm-server.regtank.com/oauth/token \
  -d "grant_type=client_credentials" \
  -d "client_id=$REGTANK_CLIENT_ID" \
  -d "client_secret=$REGTANK_CLIENT_SECRET" \
  | jq -r .access_token)

## 2. Screen an individual (Acuris KYC v2)
curl -sX POST https://$TENANT-server.regtank.com/v2/kyc/exchange/input \

        "referenceId": "user-001",
        "enableOnGoingMonitoring": true }'
# → KYC00121

Authentication

All Exchange API calls require a JWT bearer token issued via OAuth2 client credentials. Tokens are valid for 1 hour — refresh proactively.

Heads up — two hosts. The token endpoint lives on the OAuth host (crm-server.regtank.com); every other request goes to your per-tenant host ({tenant}-server.regtank.com).

Environments

EnvironmentOAuth hostExchange host
Productioncrm-server.regtank.com{tenant}-server.regtank.com
Stagingcrm-staging-server.regtank.com{tenant}-staging-server.regtank.com

Errors

The Exchange API uses conventional HTTP status codes and a uniform JSON error body.

CodeMeaningWhat it usually means
200OKRequest accepted; for v2 the body holds the systemId.
400Bad RequestField missing or fails validation. Inspect the errors map.
401UnauthorizedToken missing or expired — request a new one.
500–511Server errorOpen a support ticket with the timestamp and path values.

Rate limits

Per-tenant defaults: 20 req/s on submit endpoints, 60 req/s on query endpoints. The window resets every second; bursts of up to 5 req/s above the cap are absorbed.

Exceeding the limit returns 429 Too Many Requests with a Retry-After header in seconds.

Submit a KYC screening (v2)

Screen an individual against Acuris PEP, sanctions and adverse-media lists. Returns the systemId directly so you can poll or correlate webhook events.

Body parameters

surnamerequired*string · max 100 — Individual's last name.
forenamerequired*string · max 100 — First name.
middlenamestring · max 100
genderenum · MALE / FEMALE / UNSPECIFIED
dateOfBirthstring · ISO date (YYYY-MM-DD)
nationalityenum · ISO 3166 country code (e.g. SG, US)
countryOfResidenceenum · ISO 3166 country code
address1 · address2string · max 255
emailstring · email format
phonestring · max 100
governmentIdNumberstring · max 100
idIssuingCountryenum · ISO 3166 country code
assigneeemail · compliance officer who reviews the case
referenceIdwebhookstring · max 100 — your own identifier; required when ongoing monitoring is on
enableReScreeningboolean · default true
enableOnGoingMonitoringboolean · default false — push webhook on changes

* You must supply either both surname + forename or a single fullname.

Returns

200 OK · text/plain — the assigned systemId, e.g. KYC00121.

Query a KYC record

Pass systemId, referenceId, or both. At least one is required.

Query parameters

systemIdstring — e.g. KYC00001
referenceIdstring — your own identifier

If you pass both, the result is the intersection (records matching both).

curl "https://$TENANT-server.regtank.com/v1/kyc/exchange/query?systemId=KYC00001" \
  -H "Authorization: Bearer $TOKEN"
records = requests.get(
    f"https://{tenant}-server.regtank.com/v1/kyc/exchange/query",
    headers={"Authorization": f"Bearer {token}"},

Webhooks

Subscribe to push notifications when a KYC / KYB / KYT record changes status, hits a new sanctions list, or shows a new on-chain transaction. Configure your callback URL in the Regtank portal under Settings → Webhooks.

Event payload

{
  "eventType": "KYC_UPDATED",
  "systemId": "KYC00121",
  "referenceId": "user-001",
  "status": "COMPLETED",
  "riskLevel": "HIGH",
  "riskScore": 87,
  "hitLists": ["PEP", "SANCTIONS_OFAC"],
  "updatedAt": "2026-05-26T10:00:00Z"
}

Signature verification

Every webhook ships with two headers:

X-Regtank-TimestampUnix seconds when the event was sent.
X-Regtank-SignatureHMAC-SHA256(secret, timestamp + "." + raw_body) as hex.

Reject any webhook whose signature does not match, or whose timestamp is more than 5 minutes stale.

import hmac, hashlib

def verify(secret: bytes, body: bytes, ts: str, sig: str) -> bool:
    expected = hmac.new(secret, f"{ts}.".encode() + body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, sig)

Retry policy

Failed deliveries (non-2xx response or timeout > 10 s) retry with exponential backoff: 1 m, 5 m, 30 m, 2 h, 12 h. After 5 failures the event is dropped — recover by re-querying the affected records.
